# DS 작성 규격 v3 (내부 지침 · 이 파일은 산출물이 아님)

## 파일 구조
각 메뉴 DS 파일(`docs/ds/pages/{menuId}.md`)은 다음 순서로 작성한다.

1. `# {메뉴명} DS`
2. 메타 목록: `- Menu ID: {menuId}` / `- Registry: docs/ds/screen-registry.json` / `- Baseline: 2026-08-05 코드 기준`
3. Screen ID별 섹션 (Registry의 dsNo 순서)
4. `## 분석 파일` 목록
5. `## 미구현·확인필요 요약`

## Screen ID 섹션
제목: `## {ScreenID} — {한국어 화면명} · {한국어 상태명}`
상태명: Default=기본 상태, Loading=로딩 상태, Empty=빈 상태, Error=오류 상태

표(컬럼 순서 고정, 6열):

| DS No. | Section명 | Screen ID | 구분 | 상세 사양 | 비고 |

같은 Screen ID에 대해 Visible / Invisible / Tracking / Design 4행을 각각 작성한다.
DS No., Section명, Screen ID는 4행 모두 동일 값으로 반복 기재한다(병합 금지, Confluence에서만 병합).
해당 사항 없으면 `-`.

## 상세 사양 문체 규칙 (엄수)
- 모든 항목은 공백 없는 `-라벨.NN: 내용` 형식. 항목 구분은 `<br>` 하나만 사용(빈 줄 금지).
- 한국어 기획자·운영자·디자이너가 읽는 업무 사양서 문체. 한 문장에 한 규칙.
- 영어 설명문 금지. 코드를 읽어야 이해되는 문장 금지.
- 컴포넌트명·함수명·변수명·파일경로·props·훅·JSX·Tailwind 클래스명·CSS 변수명은 상세 사양에 쓰지 않고 비고의 `기술근거.NN:`으로 옮긴다.
- 화면에 실제 노출되는 영문 문구, API 경로, 이벤트명 등 대조에 필요한 고유 식별자는 원문 유지 가능.
- 라벨 사용 순서 권장: 정의, 구성, 표시, 문구, 조건, 상태, 정렬, 초기값, 액션, 검증, 예외, 데이터, 미구현.
- 추측 금지. 확인이 필요한 내용은 상세 사양이 아니라 비고에 `⚠️ 확인 필요.NN: 내용`으로 기재.

## 구분별 내용
- Visible: 실제 렌더링되는 제목·문구·버튼·입력·목록·표·배지·안내 문구.
- Invisible: 진입 조건, 초기값, 데이터 소스, API, 검증, 계산, 분기, 상태 전환, 이동, 저장. 미구현은 `-미구현.NN:`.
- Tracking: 실제 추적 코드가 있을 때만 이벤트명·함수명. 없으면 `-`.
- Design: 시각 속성만. 한국어 속성명(배경색·글자색·너비·높이·안쪽 여백·바깥 여백·요소 간격·모서리·테두리·그림자·글자 크기·글자 굵기·행간)을 쓰고 색은 `연한 초록색(#F5FAF6)`처럼 한국어 색상명+HEX, 크기는 px/rem 실제 값. Tailwind 클래스/CSS 변수명은 비고 기술근거로.
