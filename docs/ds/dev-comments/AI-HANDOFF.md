# AGDICT 다른 AI 시작 가이드

이 파일은 다른 AI나 에이전트에게 AGDICT 개발자 댓글 검토 업무를 넘길 때 쓰는
시작 지침이다.

## 함께 제공할 파일

1. `WORKFLOW.md` — 단일 실행 기준
2. `RESOURCES.md` — 고정 연결 대상
3. 필요 시 `AGENTS.md` 또는 `CLAUDE.md` — 앱 전역 컨벤션

## 첫 메시지 권장 문구

```markdown
첨부한 AGDICT `WORKFLOW.md`와 `RESOURCES.md`를 이 작업의 최우선 기준으로 사용해 주세요.

개발자 댓글을 검토할 때 반드시 다음 순서를 지켜 주세요.

1. 댓글을 요청 및 DS No.별로 분리
2. Confluence 현재 DS 원문 확인
3. GitHub main 실제 코드와 HEAD SHA 확인
4. Lovable 현재 관련 파일과 최신 commit SHA 확인
5. Lovable/GitHub SHA 및 댓글 관련 핵심 파일 교차 비교
6. 개발자가 제시한 gap/drift/helper 문서 존재 여부 확인
7. 이미 현재 DS에 같은 의미가 있는지 확인
8. 요청별 판정과 할 일을 분리

판정 상태는 아래만 사용해 주세요.
- 🟢 이미 반영
- 🟠 사양서 수정 필요
- 🔵 Lovable 수정 필요
- 🔴 근거 불일치
- 🟡 판정 보류
- ⚪ 확인 불가

답변 형식은 반드시 다음 순서로 작성해 주세요.

① 🔑 쉬운 상황 요약
② 개발자 댓글 처리 결과 (`요청 | 판정 | 할 일` 표)
③ 내가 실제로 수정할 사양서
④ 추가 확인/보류
⑤ 개발자에게 남길 댓글
⑥ 참고 근거

주의:
- GitHub만 확인하고 Lovable을 확인했다고 말하지 마세요.
- Lovable 코드 확인과 프리뷰 화면 시각 확인을 구분하세요.
- 개발자 근거 파일이 없어도 실제 코드로 검증 가능하면 계속 검토하세요.
- 이미 같은 의미가 현재 DS에 있으면 중복 수정하지 마세요.
- 개발자 주장과 현재 Lovable/GitHub가 직접 충돌하면 사양서를 수정하지 마세요.
- 외부 시스템 실제 수정은 별도 승인 전까지 하지 마세요.
```
